# ATLAS NEXT ARCHITECTURE
## Концепция развития Atlas v2.0 → v3.0

> **Документ описывает долгосрочное направление развития Atlas как персональной AI-операционной системы.**
> Это не замена существующей архитектуры, а стратегическое видение следующих этапов.

---

# Главная идея

Atlas не должен быть просто AI-агентом или очередной оболочкой над LLM.

Конечная цель —

> **Atlas — персональная AI-операционная система (AI Operating System), объединяющая память, модели, инструменты, проекты и знания в единую экосистему.**

Модели должны стать взаимозаменяемыми вычислительными ресурсами.

Настоящей ценностью Atlas являются:

- единый интерфейс;
- память;
- проекты;
- навыки (Skills);
- инструменты;
- автоматизация.

---

# Принцип №1

## LLM — не центр системы

Сегодня большинство AI-приложений выглядят так:

```
User
   │
  LLM
   │
 Tools
```

Atlas должен выглядеть иначе:

```
User
   │
Atlas Core
   │
 ├── Memory
 ├── Router
 ├── Agents
 ├── Tools
 ├── UI
 └── Models
```

LLM — лишь один из сервисов Atlas.

Главным компонентом становится Atlas Core.

---

# Atlas Core

Atlas Core отвечает за:

- управление агентами;
- маршрутизацию моделей;
- память;
- проекты;
- выполнение задач;
- управление инструментами;
- события;
- конфигурацию.

Все остальные компоненты работают через Core.

### Core

---

### Tools

### Agents

Высокоуровневые исполнители.

Не только историю сообщений.

Но и:

- привычки;
- стиль общения;
- предпочтения;
- технологии;
- активные проекты;
- долгосрочные цели.

# Второй мозг

Atlas должен стать интерфейсом к Obsidian.

Сценарий работы:

```
Пользователь

↓

Создает заметку

↓

Obsidian

↓

Indexer

↓

Vector Database

↓

Atlas

↓

Использует знания
```

Через несколько месяцев Atlas знает всё, что знает пользователь.

# Event Driven Architecture

Сегодня:

```
LLM

↓

Tool
```

Следующий этап:

```
Event Bus

↓

FILE_CREATED

↓

FILE_UPDATED

↓

NOTE_ADDED

↓

PROJECT_CREATED

↓

TASK_COMPLETED
```

На события подписываются сервисы.

Например:

```
NOTE_ADDED

↓

Indexer

↓

Qdrant Update
```

или

```
PROJECT_CREATED

↓

Git Init

↓

Backup

↓

Graph Update
```

Это уменьшает зависимость от LLM.

# Smart Model Router

Router должен принимать решения автоматически.

Не пользователь.

Не агент.

Именно Router.

Критерии:

- сложность задачи;
- стоимость;
- скорость;
- доступность API;
- оставшийся лимит;
- тип задачи;
- размер контекста.

---

## Пример

Программирование

↓

DeepSeek

↓

Qwen

↓

Claude

---

Документы

↓

Gemini

↓

GPT

↓

Claude

---

Генерация сайтов

↓

Groq

↓

OpenRouter

↓

Qwen

---

Если API недоступен —

Router автоматически выбирает следующий.

# Runtime Analytics

Каждая задача должна логироваться.

Например:

```
Task

↓

Model

↓

Provider

↓

Latency

↓

Tokens

↓

Cost

↓

Success

↓

Errors
```

Через некоторое время Atlas сможет самостоятельно делать выводы.

Например:

> "Groq быстрее OpenRouter для генерации лендингов."

или

> "Gemini лучше справляется с длинными PDF."

Router становится самообучающимся.

# Единая память

Память не должна принадлежать модели.

Она принадлежит Atlas.

При смене модели ничего не теряется.

Меняются только вычислительные мощности.

# Долгосрочная цель

Atlas должен стать не просто AI-агентом.

Не просто оболочкой над LLM.

И даже не просто "вторым мозгом".

## Конечная цель:

> **Создать персональную AI-операционную систему, которая объединяет знания, память, проекты, инструменты, модели и автоматизацию в единую интеллектуальную среду.**

В этой архитектуре:

- модели можно свободно менять;
- память сохраняется навсегда;
- интерфейс остаётся единым;
- знания постоянно накапливаются;
- Atlas становится умнее с каждой выполненной задачей.

Именно Atlas является продуктом.

LLM — лишь один из его компонентов.
